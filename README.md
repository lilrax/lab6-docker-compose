
# Лабораторная работа №5 — Микросервисы на Python

## 1. Описание проекта

Проект представляет собой систему из двух независимых
микросервисов, разработанных на Python с использованием FastAPI.

Система предназначена для создания и получения товаров.

Микросервисы:

1. API Gateway — принимает запросы пользователя и обращается
   к Storage Service по HTTP.
2. Storage Service — выполняет операции с товарами и
   сохраняет данные в SQLite.

Каждый сервис запускается отдельно и имеет собственные
настройки и зависимости.

## 2. Используемые технологии

- Python 3.12
- FastAPI — разработка REST API
- Uvicorn — запуск HTTP-серверов
- Pydantic — валидация входных и выходных данных
- Pydantic Settings — конфигурация через переменные окружения
- httpx — HTTP-взаимодействие между микросервисами
- SQLite — постоянное хранение товаров
- pytest — автоматическое тестирование
- pytest-cov — измерение покрытия тестами
- Ruff — проверка и форматирование кода
- Git — контроль версий

## 3. Архитектура

Система состоит из двух отдельно запускаемых приложений.

Клиент
  |
  | HTTP-запрос
  v
API Gateway (127.0.0.1:8000)
  |
  | HTTP-запрос через httpx
  v
Storage Service (127.0.0.1:8001)
  |
  v
SQLite (data/items.db)

API Gateway не обращается к SQLite напрямую.

Storage Service отвечает за работу с базой данных.

## 4. Возможности

- Создание товара через POST /items.
- Получение товара по ID через GET /items/{item_id}.
- Проверка входных данных с помощью Pydantic.
- Автоматическая документация Swagger UI.
- Обработка ошибок HTTP 404 и 422.
- Обработка недоступности Storage Service через HTTP 503.
- Обработка некорректных ответов Storage через HTTP 502.
- Настраиваемый таймаут HTTP-запросов.
- Логирование ошибок.
- Изолированное автоматическое тестирование.

## 5. Установка

Требуется установленный Python 3.12.

Все команды ниже предназначены для Windows PowerShell.

### 5.1. Установка Storage Service

Откройте терминал в корне проекта:

```powershell
cd storage
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

При необходимости измените настройки в файле `.env`.

### 5.2. Установка API Gateway

Откройте другой терминал в корне проекта:

```powershell
cd api-gateway
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

При необходимости измените настройки в файле `.env`.

Для каждого сервиса используется собственное виртуальное
окружение Python.

## 6. Настройки сервисов

### Storage Service

Пример файла `storage/.env`:

```env
STORAGE_HOST=127.0.0.1
STORAGE_PORT=8001
STORAGE_DB_PATH=data/items.db
STORAGE_LOG_LEVEL=info
```

### API Gateway

Пример файла `api-gateway/.env`:

```env
GATEWAY_HOST=127.0.0.1
GATEWAY_PORT=8000
GATEWAY_STORAGE_URL=http://127.0.0.1:8001
GATEWAY_REQUEST_TIMEOUT=5
GATEWAY_LOG_LEVEL=info
```

Настройки читаются с помощью Pydantic Settings.

## 7. Запуск

Для работы системы необходимо запустить два сервиса.

### 7.1. Запуск Storage

В терминале из папки `storage`:

```powershell
.\.venv\Scripts\python.exe run.py
```

Storage запускается по адресу:

http://127.0.0.1:8001

Swagger UI:

http://127.0.0.1:8001/docs

### 7.2. Запуск Gateway

В другом терминале из папки `api-gateway`:

```powershell
.\.venv\Scripts\python.exe run.py
```

Gateway запускается по адресу:

http://127.0.0.1:8000

Swagger UI:

http://127.0.0.1:8000/docs

Для остановки каждого сервера нажмите Ctrl+C
в соответствующем терминале.

## 8. Демонстрация работы API

### Создание товара

Откройте:

http://127.0.0.1:8000/docs

Выберите POST /items, нажмите Try it out.

Пример JSON:

```json
{
  "name": "Mouse",
  "price": 1500,
  "quantity": 5
}
```

Нажмите Execute.

Ожидаемый HTTP-код: 201 Created.

Сервер возвращает созданный товар с уникальным ID.

### Получение товара

В Swagger UI выберите GET /items/{item_id}.

Введите ID ранее созданного товара.

Ожидаемый HTTP-код: 200 OK.

Если товара с таким ID нет, ожидается 404 Not Found.

### Некорректные данные

Попробуйте создать товар с отрицательной ценой:

```json
{
  "name": "Mouse",
  "price": -100,
  "quantity": 5
}
```

Ожидаемый HTTP-код: 422 Unprocessable Entity.

## 9. Демонстрация отказоустойчивости

1. Запустите Storage и Gateway.
2. Создайте товар через Gateway.
3. Получите товар по ID — ожидается 200 OK.
4. Остановите только Storage нажатием Ctrl+C.
5. Повторите GET через Gateway.
6. Gateway должен вернуть 503 Service Unavailable.
7. Проверьте предупреждение в логах Gateway.
8. Снова запустите Storage.
9. Повторите GET — ожидается 200 OK.

Пример ответа при недоступности Storage:

```json
{
  "detail": "storage service unavailable"
}
```

При этом сам API Gateway продолжает работать.

## 12. Основные принципы

### Микросервисная архитектура

Приложение разделено на два независимых сервиса,
взаимодействующих по HTTP.

### Разделение ответственности

Gateway отвечает за внешний API и взаимодействие с клиентом.

Storage отвечает за доступ к данным и их сохранение.

### Слоистая архитектура

Каждый сервис разделён на слои:

- API — обработка HTTP-запросов.
- Domain — бизнес-логика.
- Storage — взаимодействие с внешним хранилищем.

### Dependency Injection

Зависимости передаются в сервисы извне.

Это позволяет заменять настоящие репозитории тестовыми.

### Protocol

Интерфейс репозитория описывается с помощью typing.Protocol.

Бизнес-логика не зависит от конкретной реализации хранилища.

### Обработка отказов

При недоступности Storage Gateway возвращает HTTP 503,
а не завершает работу приложения.
